# Alpha 0.1 实施与验收记录

范围依据：开发计划 W10 / G2 的内部合成数据闭环。实现已覆盖记录保存 → 转写／脱敏 → 客户及事实分别确认 → 档案与来源 → 纠错 → 手动任务。**工程自动化通过不等于 G2 人工签署，更不等于 G4 真实资料准入。**

| 计划内容 | 交付 | 验证 |
| --- | --- | --- |

## 当前自动化结果

- Python：26 个用例在 SQLite 和 PostgreSQL 17 通过；包括音频失败及重试、多人归属、幂等、隔离和证据校验。
- Flutter：6 个测试通过，静态分析无问题。测试使用模拟 HTTP 和设备密钥存储替身，不代表麦克风或 Keychain 真机验证。
- `scripts/alpha_smoke.py`：临时账户与临时数据库，真实 HTTP 服务和独立 Worker，验证完整文字链路及 API 重启后持久化。
- CI 扩展为 Python、PostgreSQL、Flutter、Android debug APK、iOS simulator build；最终结果以当前提交的 Actions 为准。
- 本地 Vosk 中文模型已加载并完成合成语音推理；espeak 合成语音识别明显失真，**未通过 ASR 准确率验收**。API 测试中的确定性转写替身仅验证流程。
- Ollama 适配器通过契约、越界证据和脱敏测试；当前环境未安装并运行实际 LLM，不能宣称已完成模型质量评测。

## 设计取舍和适用边界

1. 单体 API + 独立 Worker；数据库队列是权威，Outbox 留存同事务事件，不引入 RabbitMQ 发布器。以轮询完成 Alpha，托管队列在 RC 单独实施。
2. 业务 JSON 和音频均加密保存。Alpha 使用环境变量数据密钥和数据库音频 BLOB；生产 KMS/信封加密、对象存储、轮换、RLS 不在本次完成声明中。
3. 关键词搜索在租户内解密扫描，适合内部验证，不作为中远期千万客户容量方案。
4. 默认规则提取；可选本机 Ollama 只对已脱敏的来源句子做筛选，不能凭模型生成新事实；不访问第三方 LLM。模型不能执行工具或外发消息。
5. 多人以候选事实的原文片段为分配单位。同一句混合多人时先编辑拆句再分配；无法识别的人物仍由人工确认，绝不以候选名作为自动归档依据。
6. 用量仅记录已交付阶段，不收费；同修订同阶段不重复记账，ASR 已成功后的提取重试不再转写。免费／收费订阅、预留预算和支付对账属于 RC。
7. 删除记录会清空原文载荷、删除音频并使来源事实失效；保留墓碑阻止离线复活。历史事实密文、备份与账户级隐私删除传播留待 RC，不能宣传为完整隐私擦除。
8. 登录限流为单进程每 IP 每分钟 20 次，适用于私有内部环境；不是生产分布式防滥用方案。
