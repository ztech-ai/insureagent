# 数据库与持久化详细设计

PostgreSQL 是客户、记录、事实、任务、权益和事件的权威来源。录音存放于加密对象存储；向量及搜索索引可重建，不承载唯一事实。首期使用托管 PostgreSQL 16 高可用实例，按真实小版本检查 pgvector 插件支持。

## 核心表和索引

所有业务数据都以 tenant_id 为首要隔离维度，复合主键与外键均包括 tenant_id，防止跨租户引用。示例 UUID 由应用服务使用 UUIDv4 生成。

| 表 | 主要字段与约束 | 索引与用途 |
| --- | --- | --- |
| tenant、app_user | tenant_id、user_id、状态、时区、账号注销状态 | 用户与租户归属；不能信任客户端自行传入的租户 |
| customer | tenant_id、customer_id、加密姓名、阶段、status、version、deleted_at | PK tenant_id 加 customer_id；列表索引 tenant_id、status、updated_at |
| customer_identifier | identifier_id、customer_id、类型、加密值、租户 HMAC 令牌、验证状态 | tenant_id 加类型加令牌，允许同一值对应多个客户 |
| record | record_id、client_record_id、来源、发生时间、对象引用、storage_state、revision、version、deleted_at | 每租户 client_record_id 唯一；列表索引 tenant_id 加时间 |
| record_revision | record_id、revision、加密原文引用、来源、发生时间；复合主键 tenant_id/record_id/revision | 保存用户修订和处理版本；不在明文 JSONB 中保存原文 |
| record_person_link | record_id、revision、customer_id、片段范围、角色、确认状态 | 关联同一记录的多个客户，并以来源版本约束 |
| customer_fact | fact_id、customer_id、类型、加密值或引用、来源记录和片段、状态、版本、发生时间、有效期 | customer_id 加状态加类型；人工更正产生新版本 |
| customer_relationship | 双方客户或被提及人物、关系、来源、状态、版本 | 默认不创建独立客户；来源删除时重新计算 |
| suggestion、followup_task | 客户、内容引用、依据版本、状态、到期时间、过期时间 | 已删除客户不可查询；任务到期索引不存放明文内容 |
| model_run | 类型、模型及提示版本、token、成本、输入摘要、状态、供应商请求 ID | 无提示词或模型原文；建议内容另行加密存储 |
| entitlement、usage_reservation、usage_ledger | 用户、周期、额度、预留、结算、订单状态 | 租户和周期原子扣减，账本可审计；失败退款或释放 |
| job、outbox、processed_event | 任务或事件 ID、租户、类型、对象版本、状态、租约、尝试数 | 事件至少一次处理，幂等键和业务结果约束共同防重 |
| consent_evidence、deletion_request、audit_log | 告知及依据、删除范围、元数据审计 | 仅存必要元数据与安全引用，敏感证据加密 |
| search_chunk | tenant_id、customer_id、来源和版本、脱敏片段、768 维向量、模型版本、状态 | 按 tenant_id 和状态候选过滤；删除同步失效 |

## 核心约束示例

以下示例展示隔离和幂等关系，并非完整生产迁移。加密封装、阶段枚举、审计、归档、访问控制和所有其他表需要在真实迁移中补齐。

```sql
CREATE TABLE customer (
    tenant_id uuid NOT NULL,
    customer_id uuid NOT NULL,
    display_name_cipher bytea,
    status text NOT NULL DEFAULT 'active',
    version bigint NOT NULL DEFAULT 1,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    deleted_at timestamptz,
    PRIMARY KEY (tenant_id, customer_id)
);

CREATE TABLE record (
    tenant_id uuid NOT NULL,
    record_id uuid NOT NULL,
    client_record_id uuid NOT NULL,
    storage_state text NOT NULL CHECK (storage_state IN ('stored', 'deleted')),
    revision integer NOT NULL DEFAULT 1,
    version bigint NOT NULL DEFAULT 1,
    object_ref text,
    occurred_at timestamptz,
    created_at timestamptz NOT NULL DEFAULT now(),
    deleted_at timestamptz,
    PRIMARY KEY (tenant_id, record_id),
    UNIQUE (tenant_id, client_record_id)
);

CREATE TABLE record_revision (
    tenant_id uuid NOT NULL,
    record_id uuid NOT NULL,
    revision integer NOT NULL CHECK (revision > 0),
    transcript_cipher_ref text,
    created_at timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (tenant_id, record_id, revision),
    FOREIGN KEY (tenant_id, record_id) REFERENCES record (tenant_id, record_id)
);

CREATE TABLE record_person_link (
    tenant_id uuid NOT NULL,
    record_id uuid NOT NULL,
    customer_id uuid NOT NULL,
    revision integer NOT NULL,
    segment_no integer NOT NULL,
    status text NOT NULL,
    PRIMARY KEY (tenant_id, record_id, revision, segment_no, customer_id),
    FOREIGN KEY (tenant_id, record_id, revision) REFERENCES record_revision (tenant_id, record_id, revision),
    FOREIGN KEY (tenant_id, customer_id) REFERENCES customer (tenant_id, customer_id)
);
```

标识令牌不设全局唯一约束，电话可能共用；确定用户同意或其他合法依据、是否存储原值和保留时间后，才写入加密值和租户专属 HMAC。客户新增的额度判断和插入必须在同一事务内串行化或用可证明的原子配额策略，避免并发超出客户上限。

## 行级安全与连接池

运行角色无超级用户、BYPASSRLS、表所有权或 DDL 权限；服务在每个事务内从已验证的身份上下文设置本地租户变量，结束时由事务清理。示例如下，所有其他租户表需同等策略：

```sql
ALTER TABLE customer ENABLE ROW LEVEL SECURITY;
ALTER TABLE customer FORCE ROW LEVEL SECURITY;
CREATE POLICY customer_tenant_policy ON customer
  FOR ALL TO app_runtime
  USING (tenant_id = NULLIF(current_setting('app.tenant_id', true), '')::uuid)
  WITH CHECK (tenant_id = NULLIF(current_setting('app.tenant_id', true), '')::uuid);

BEGIN;
SELECT set_config('app.tenant_id', :tenant_id_from_verified_session, true);
SELECT customer_id FROM customer WHERE status = 'active';
COMMIT;
```

每个 AsyncSession 只属于一个请求或后台任务，不跨并发协程共享。事务池必须验证 SET LOCAL、连接复用和异常退出；后台工作进程同样在事务里设置租户。数据库 RLS 是额外防线，不取代 API 授权和参数化查询：如果攻击者控制了数据库会话或能执行任意 SQL，普通自定义会话变量可能被改写。表所有者通常可绕过 RLS，超级用户及 BYPASSRLS 角色始终绕过；特权角色仅用于受控迁移或运维。[PostgreSQL 行级安全](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)。

跨租户调度或 outbox 投递使用单独、最小权限的服务角色，只读必要的非明文元数据；不能借此读取客户原文。所有新增表都应有自动化测试验证 RLS 和复合外键。

## 一致性和事务边界

记录确认、事实写入、版本递增与 outbox 事件放入同一数据库事务。更新采用 version 或 record_revision 的乐观锁；用户修改和删除后，异步任务的旧版本提交失败，不能回写。

对 OSS 不假设与数据库分布式事务。上传对象先处于临时状态；提交 API 校验对象，落库成功后成为正式引用，并在失败重试时复用幂等键。清理器删除超过期限且没有正式引用的临时对象。客户端看到“云端已保存”前，系统必须确认对象和记录都已达到既定持久性。

用户资料、任务、权益在一个租户内完成事务；不要把向量库或模型调用纳入数据库事务。删除先在权威库设置访问失效与墓碑，再通过 outbox 推进对象、索引、队列和供应商清理。

## 分片与增长

试点使用单个高可用主库，冷备和读副本依实际需要配置。增长阶段先分离 search_chunk 和历史索引，再评估客户业务库按 tenant_id 的稳定哈希拆为有限数量共享分片；一个租户的事务、outbox 和权限信息放同一分片，不为每个销售人员建库。

每个库分片可再按 tenant_id 哈希做有限分区；分区表的唯一约束必须包含分区键。路由由服务端维护 tenant_id 到 shard 的版本化映射，迁移按快照、增量同步、双读校验、短暂停写、切换和回滚执行。不要跨分片做同步事务；跨租户报表仅使用已授权的去标识化统计数据。

基准假设 3500 万客户、每客户 4 个精选片段，即 1.4 亿向量；768 维 float32 裸向量 430 GB，行与索引、副本、备份另计。按每月 510 万条新增记录估算，24 个月最多约 1.224 亿条新增记录；真实留存、去重和归档会改变此数值。

## 备份与恢复

数据库开启加密备份、WAL 连续归档和时间点恢复；对象启用适当冗余及生命周期。规划区域级 RPO 15 分钟、RTO 4 小时的生产目标，依赖数据库、对象和删除墓碑的共同恢复点、跨区复制、可用的冷备资源及定期演练；试点未配齐时明确不承诺该区域级目标。

删除墓碑和撤权状态必须以不早于恢复点的可靠方式跨区域保存。恢复实例在核对墓碑完整性并重放删除之前不对外开放；若无法确认完整性，继续封闭恢复环境并升级处理。备份随周期过期，不把删除在线数据误称为已即时清除备份。

## 操作限制

密码、客户姓名、电话、证件、转写和音频不能出现在 SQL 日志、慢查询明文参数、APM、迁移脚本、监控标签或测试数据中；生产排错使用经授权的脱敏样本。DDL 通过 Alembic 先扩展后切换，验证新旧版本兼容，灰度后清理旧字段。

## 补充实体和约束

新增 contact_policy、opportunity、task_outcome、device_session、device_sync_cursor、notification_delivery、upload_session、export_job、knowledge_document、knowledge_version 与 suggestion_evidence。fact_evidence 单独关联事实与多条来源；摘要与建议也用多对多证据表维护，删除一个来源后仅剩余有效依据能支持该结论时才保留，否则撤回或重算。

统一记录状态分维度存储：record 仅负责 storage_state、current revision 及访问状态；record_processing 保存 stage/status/attempt/error；record_person_link 管归属；customer_fact 管确认。需要事务或触发器确保 record 的当前 revision 有对应版本行；版本、事件与资料一次提交。

模型运行、账本、事件、审计增长可能远大于客户表：按月分区、按租户限制，保留期由审计与最大重放窗口确定。不能只估算向量容量。用户分页使用 (updated_at, id) 游标，限制批量和最大页长，避免大偏移分页。

离线同步返回递增变更游标及 tombstone；提交含 base_version、client_operation_id 和 device_id。服务器不采用最后写入胜出；冲突返回 409 和差异，待用户取舍。过期游标返回需重新同步；重装或恢复备份的设备不能绕过墓碑恢复已删除客户。服务端能使离线设备会话失效，但无法保证立即擦除断网设备，因此本地密钥、缓存时限和重新登录解锁仍是必要边界。
