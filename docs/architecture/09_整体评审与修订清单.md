# 整体方案评审与修订清单

本轮审查涵盖产品需求、九份云端详细设计和成本脚本，结论是：现有数据隔离和受控 Agent 的方向可继续采用，但上线前需把部分成功、客户经营状态、多设备、检索删除一致性和套餐压力成本落实。以下问题已补入相关设计；“已修订”只表示设计文件更新，不代表服务已经实现或压测通过。

## 移动端补齐的使用路径

主路径为今天 → 口述记录 → 已保存并处理 → 确认客户与事实 → 客户详情 → 采纳建议并编辑任务 → 跟进 → 联系结果。原型还展示权限拒绝、断网草稿、客户同名、AI 暂不可用、额度用尽、暂停联系、来源纠错和删除确认，避免只设计成功状态。

客户经营建议只显示证据、可讨论的问题和下一步；不展示无依据的成交概率、财富分数、投保资格或保证收益。所有示例姓名和记录均为虚构，原型无真实录音、支付、消息外发或数据删除。

## 上线前仍需验证

| 责任角色 | 必须获得的证据 |
| --- | --- |
| 产品与保险业务 | 目标用户可独立完成记录和确认；客户同意/其他依据及保险机构资料的合法使用路径 |
| 安全与法律 | ASR、LLM、推送、短信、支付及诊断 SDK 数据路径与协议；权利请求、删除、账号恢复可执行 |
| AI 与测试 | 同名、多人物、方言、敏感标识和提示注入样本，分层报告准确率及置信区间 |
| 后端与运维 | 实际账号的模型和 KMS 配额，负载压测、故障及墓碑恢复演练 |
| 商业负责人 | 平均与额度满额两种成本、渠道分成和资源报价，自建 ASR 单独估算 |

当前交付是修订后的设计和可交互 UI 原型，不是已上线 APP。下一阶段可以按 P0 项拆为研发任务，再用真实授权样本及目标机型验证。
