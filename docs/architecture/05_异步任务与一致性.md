# 异步任务调度与一致性设计

录音处理、事实提取、索引、客户建议、提醒和删除均可能跨多个服务。系统按“至少一次传递、业务效果幂等、版本校验”设计；不假定队列、模型调用和数据库存在全局事务。

## 事件传递

业务事务同时写入权威数据和 outbox，避免提交资料后因进程退出漏发消息。Outbox 只含 tenant_id、事件 ID、类型、对象 ID 和版本、时间及 trace_id，不含客户原文。独立投递器分批租用待发项、提交租约，再发送持久化消息并等待 broker 确认；确认后标记已发送。确认与标记之间若进程故障可能重复投递，消费者必须防重。

```json
{
  "event_id": "8f53b58b-fc14-44e6-bb08-684a154e8e63",
  "schema_version": 1,
  "event_type": "record.confirmed",
  "tenant_id": "69f22e43-702e-44b2-a931-d4f6a6e8aa69",
  "entity_id": "6506c4b8-29b4-4b8a-814a-14f18bc4551f",
  "entity_version": 3,
  "occurred_at": "2026-11-14T00:00:00Z",
  "trace_id": "opaque-trace-id"
}
```

事件按版本化模式解析，消费者验证租户、授权和当前对象版本。消费者用 consumer_name 加 event_id 建立去重记录，并与本地数据库效果同事务提交；成功提交后再 ACK。若外部操作不是本地事务，如模型调用，额外使用业务任务状态机和供应商幂等/查询能力，不能仅靠 processed_event 宣称外部恰好调用一次。

## 任务状态与租约

job 包含 tenant_id、job_id、type、entity_id、source_version、idempotency_key、priority、due_at、lease_owner、lease_until、attempt、deadline、status 和 last_error_code。状态为 queued、leased、running、succeeded、retry_wait、failed、cancelled、expired。

工作进程用有界批量的 SELECT FOR UPDATE SKIP LOCKED 获取任务，写入可过期租约后提交；执行中周期续租。进程异常或过期后任务可由其他进程领取，但实际执行前后均需验证租约、版本、删除和权限；旧工作进程失去租约后不得提交结果。更新用条件 UPDATE 和受影响行数防止竞态。

业务去重键以租户、任务类型、客户或记录、来源版本及计划周期构成；人工强制刷新通过独立 request_id 明确创建新任务。对同一次后台调度，多次发现同一客户不得重复产生建议或提醒。

## 定时经营和公平性

- 分析：确认记录后按客户防抖约 5 分钟；付费用户每周最多选 25 名符合条件的客户自动分析，单客户冷却 7 天。按每月额度和人工请求共同计数，生成计划随产品验证调整。
- 日程：按用户时区计算 due_at 并存 UTC；处理夏令时重复/缺失时间和时区变更。提醒只给已确认任务，去重键包含任务 ID、提醒时间和渠道；通知正文默认不显示敏感内容。
- 删除：高优先级任务即刻撤销读取与运行，再清理索引、缓存、对象和第三方；失败持续告警直至处理完成。
- 公平性：队列按租户和优先级调度，每用户并发上限、全局 token/RPM 桶、计划任务随机抖动；交互请求和记录优先于可延迟的后台分析。不能让单个重试租户耗尽全局配额。

调度器按时间桶和租户分片扫描到期任务，避免为每个客户创建独立云定时器或每夜重扫全部客户。将 backlog 年龄、预计完成时间、过期任务、死信和租户饥饿纳入告警。

## 权益预留与计量

权益服务以 tenant_id、周期和额度类别作为原子账本键。请求受理时校验套餐，原子预留客户数、录音时长或建议次数；预留设有效期，长任务续租；执行前核验预留和权益快照。按成功交付的阶段结算，未交付阶段失败、安全阻断或取消释放；中途到期是否完成以开始时的权益快照及产品规则为准，后续新任务不得使用旧权益。

外部请求超时不代表供应商未处理或未计费。用户侧未交付阶段不扣额度，已可用阶段不因下游失败重复扣减；供应商成本仍记录为不确定或实际账单成本；重试先查状态，不能把用户额度与供应商账单等同。并发请求、重复支付回调及续期/退款乱序按业务键和订单版本幂等处理。

## 重试与死信

对 429、网络故障和可恢复 5xx 按指数退避加随机抖动重试；鉴权失败、格式错误、政策阻断和额度不足不自动反复重试。每任务限制次数、最大存活时间和成本；到期进入失败或死信，向用户展示可行动状态。死信只保存最小元数据，操作员重放须重新验证租户、记录版本、授权和删除墓碑。

## 容量与恢复

目标情景记录约 17 万条/日，70% 集中 10 小时、3 倍突发约 10 条/秒；每条可能展开多个消息与模型请求，不能把 10 当成 RabbitMQ 总消息速率。备选 paraformer-realtime-v2 文档列示每秒 20 次建连，示例峰值约 9.92 次/秒；长录音重连与重试会增加请求。需单独验证同时进行的会话数、供应商实际配额、队列容量及 SLA，不能仅据 RPM 推断容量。

重启后重新领取超时租约、扫描未投递 outbox 并保留原事件 ID；数据库和队列恢复到不同时间点时，依靠 outbox/业务任务状态重放。检查点、去重记录和删除墓碑保留期必须覆盖最大消息重放与备份恢复窗口；过期之前不得让陈旧事件重新生成已删除内容。

## 队列与任务的单一权威

数据库 job 是唯一运行状态。outbox 投递 job.available 消息，消费者先通过数据库原子领取，再 ACK 通知；如果未领取不执行。租约超时由调度器重发通知，因此通知丢失不丢任务。定时器、消费者或人工重放都不得绕过同一领取函数。领取产生递增 fencing_token，最终提交必须匹配 token、有效租约、输入 revision、当前 policy_epoch；只检查工作进程名称不够。

ASR 完成可读转写后结算 ASR；抽取候选可用后单独结算提取。客户身份待确认不产生重复调用。权益 reservation 绑定 tenant_id、计量类别、input revision、操作键和周期，最终结果与账本幂等键在同一数据库事务提交；超过期限的结果在交付前重新验证预留，不能静默给用户新增扣费。

## 联系偏好与通知

勿扰、暂停、安静时段及撤权在筛选、执行、展示和通知前重验。建议生成不自动创建提醒。基础手动任务和提醒是免费权益；付费仅决定自动经营分析。明确区分任务 due_at 与提醒 delivery_at，支持延期和过期汇总，不对每个逾期任务无限重发。

推送使用 APNs 及目标 Android 渠道适配，登记设备 token、权限、失效和最后活跃；离线或通知被拒绝时保留应用内收件箱。receipt 只代表渠道接收，不等于用户阅读；payload 不含客户身份，点击后重新登录校验。异常重复和未送达由 notification_delivery 去重、限次重试并记录状态。
