# 部署高可用与运维详细设计

首期选定中国大陆一个地域的两个可用区，运行无状态 API、工作进程和托管中间件。跨地域灾备是独立建设项；不能因为使用同地域双可用区就宣称达到区域灾难恢复目标。

## 部署拓扑

| 资源 | 试点参考 | 后续扩展 |
| --- | --- | --- |
| 接入层 | 云负载均衡、TLS、必要的 WAF；API 至少两个可用区各一个实例 | 按 CPU、请求、连接和错误扩容；限制客户端上传和请求体 |
| 业务进程 | Python FastAPI 容器，试点各区至少 1 台 4C8G ECS 作为规划基线 | 模块化单体，容量不足后按有界上下文拆服务 |
| 工作进程 | 至少 2 台 8C16G ECS 分区部署；转写、脱敏、提取、索引、建议分别配置队列及并发 | 根据实际 CPU、I/O、模型限流及积压独立扩缩，不无条件同时扩 |
| 数据库 | PostgreSQL 16 托管高可用，主备跨区；实际可用区组合以地域服务为准 | 先拆向量和只读工作负载，再做有限租户分片 |
| 队列和缓存 | 托管 RabbitMQ 及 Redis，采用有 SLA 的高可用规格 | 按吞吐、积压与网络重新配置；队列不可替代数据库 |
| 文件与密钥 | 私有 OSS、KMS、短期上传凭证和生命周期 | 需要区域灾备时开启可验证的跨区副本和密钥恢复 |
| 观测 | OpenTelemetry 接入托管日志、指标与告警；时钟同步 | 聚合操作元数据，避免完整客户内容 |

ECS 规格只是试点起点，不意味着能够满足目标峰值。镜像固定摘要，Docker 和 systemd 管理重启与健康检查；需要自动弹性、复杂多服务和团队有能力管理时再评估 Kubernetes。所有服务访问使用最小 IAM，数据库、队列和工作进程位于私网；外部模型请求通过受控出口。

## 可用性指标

| SLI 与目标 | 口径 |
| --- | --- |
| 核心可用性 99.9% 每月 | 有效的登录、客户读取与记录写入请求中成功且未超时的比例；监控错误和可用时间，排除明确的用户取消与非法请求 |
| 云端保存 P95 小于 3 秒 | 已完成上传到对象存储的合规文件，从完成通知到服务端对象和数据库持久化确认；不包括客户端上传时间 |
| 转写与提取 | 90 秒录音上传成功后 95% 在 5 分钟内成功完成；失败和超时单独计算，不以快速失败充当成功 |
| 客户检索 P95 小于 500 毫秒 | 租户内常用检索、真实数据量、负载和权限过滤下的服务端时间，不包含生成模型时间 |
| 后台建议 | 权益与配额允许的定期任务 至少 95% 在计划后 24 小时内成功交付；失败另外计入错误率并及时呈现，不能用快速失败计为达标 |
| 删除可见性 | 授权撤回或删除被接受后立即阻断读取；在线物理清理目标 72 小时 |

月度 99.9% 是设计目标，不是供应商承诺；30 天约对应 43.2 分钟不可用预算。客户端弱网体验、供应商故障和对象上传失败另设监测，不用单一 API 指标代替全链路成功率。

## 队列数据库和模型弹性

工作进程按高优先级记录与用户主动问答、低优先级后台建议隔离；同时执行全局供应商 RPM/TPM 和租户配额。依据队列最旧消息年龄及处理成功率扩容，但不超过 ASR/LLM 配额；高峰可暂停后台建议，不能靠盲目增加进程突破第三方限流。

数据库使用连接池并限定各进程最大连接数；单任务单 AsyncSession。索引构建、回填和备份需避开高峰并设置 I/O 上限。对象上传校验 hash、大小、所有权和加密元数据；临时对象按周期清理。运行角色不能绕过 RLS。

## 灾难恢复

| 场景 | 目标及动作 |
| --- | --- |
| 单进程或单机故障 | 负载均衡摘除故障实例；租约到期后任务重新领取，幂等提交 |
| 单可用区故障 | 托管数据库切换、存活可用区承载；验证连接重试、容量余量和排队延迟 |
| 语音或模型供应商不可用 | 保存记录、停止不安全重试，显示处理中或失败；只切换已获批准的同地域替代服务 |
| 数据库逻辑误删 | 隔离恢复实例，依据时间点备份恢复并进行删除墓碑、授权与账本对账 |
| 整个地域不可用 | 生产目标 RPO 不超过 15 分钟、RTO 不超过 4 小时；依赖跨地域数据库、对象、密钥、删除墓碑、基础设施及切换演练 |

必须测量数据库 WAL、对象复制、KMS 密钥可用性及墓碑的一致恢复点；切换前校验密钥权限、备份和删除状态。任何一项落后导致目标不可达时，禁止对外开放可能复活数据的副本。试点仅建设双可用区时，区域级 RPO/RTO 未达成；预算和建设完成并演练通过后才能对外承诺。

## 观测与发布

指标覆盖：各 API 成功率及延迟、音频上传与持久化、ASR RPM/TPM/429 与处理时长、DLP 漏检评估及阻断、模型成本和 token、待确认积压、队列年龄、任务租约/死信、数据库连接与复制延迟、对象与 KMS 错误、RLS 越权、删除进度、每租户额度。聚合指标避免把客户身份作为标签。

发布采用扩展式数据库迁移、向后兼容事件、灰度、回滚和可恢复开关；模型与提示词独立灰度。每季度至少演练单区故障、跨区恢复和删除重放；每月演练供应商限流和死信重放。演练报告记录实际 RPO、RTO、影响及整改负责人。

事故流程以阻断扩散、保护客户和恢复服务为序；落实告警负责人、值班升级、取证和适用的通知要求。未取得授权的生产数据不得用于调试或模型评测。

## 上线资源与恢复门槛

确认 Qwen 快照实际账号 RPM/TPM、Paraformer 同时会话数、KMS 密钥操作配额、数据库连接数及 I/O 后才能签容量承诺。基础设施预算不包含受控自建 ASR 的 GPU/CPU 推理资源；若不用托管 ASR，必须替换该项成本并验证冷启动和吞吐。

上传按身份、文件时长、解码后大小和每日次数限制，防压缩炸弹、伪造类型和重试滥用；拒绝文件仍允许保存本地草稿。云服务商不可用与 KMS 不可用分别演练，KMS 故障不得退化为明文存储。

离线设备和跨地域恢复的墓碑检查以最新已接受删除的可靠水位为准，不仅是业务数据库恢复点。若最新水位无法确认，暂停对外解密读取并由恢复负责人核对，不能声称较旧备份也满足“删除不复活”。

新增上线验收：多设备编辑冲突、短信重发滥用、会话撤销、通知拒绝与离线送达、部分成功扣费、恢复购买/退款乱序、过期产品资料、勿扰期间任务、聚合来源删除以及长录音资源耗尽。测试以授权样本或合成数据完成。
